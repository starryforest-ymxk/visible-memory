# 文件格式、索引和手工编辑

## 原文与派生数据

根目录由用户配置选择，或在本次明确请求中通过 `--root` 指定。初次初始化为空库，不导入个人信息。程序版本 2.1.0 仍使用 v2 记忆格式，不修改已有 UUID、时间、原文或历史。

| 相对路径 | 职责与恢复边界 |
|---|---|
| `entries/<UUID>.md` | 唯一正式 Markdown 原文；归档保持 UUID 和路径 |
| `history/` | 实际观察到的版本、操作事件、生成页面备份及迁移记录；不自动清理 |
| `_state/vault.json` | 小型配置，`format_version = 2`、库 UUID 和操作库版本等标记 |
| `_state/operations.sqlite` | 持久请求重试凭据、操作阶段、页面归属、截短显示字段和生成文件校验；不可当缓存删除 |
| `_state/write.lock` | 单写者锁；不会自动移除遗留锁 |
| `_index/search.sqlite` | 原文的派生检索缓存，含全文与短词索引、筛选字段、内容指纹、大小和修改时间；明确重建时可再生成 |
| `INDEX.md` | 固定数量的说明、统计和五类记忆入口 |
| `USER.md` | 有效偏好的分页入口 |
| `MEMORY.md` | 有效事实、决策和经验的分页入口；笔记从首页进入 |
| `ARCHIVE.md` | 归档记忆的分类入口 |
| `catalog/<状态>/<类型>/` | `INDEX.md` 分类导航、`page-000001.md` 等内容页及必要的分级导航 |

索引数据库可以随记忆数量增大，但不整体送入模型上下文。任何数据库或总览内容都不能自动覆盖正式原文。重建 `_index` 不清空 `_state` 中的请求凭据；操作库损坏时不能从原文完整推断历史授权与重试状态。

数据库及其日志侧车文件接受与 Markdown 相同的路径、重解析点和硬链接检查。读取不通过打开数据库来恢复日志或创建文件；需要维护时报告而不偷偷写入。

## 条目格式

每个文件以 `+++` 独立行包围 TOML 文件头，后接 Markdown 正文。以下仅为示意：

```markdown
+++
id = "01234567-89ab-4cde-8fab-0123456789ab"
title = "示例：某项目的写作约定"
type = "preference"
status = "active"
tags = ["写作", "示例项目"]
created_at = "2026-09-06T12:00:00+08:00"
updated_at = "2026-09-06T12:00:00+08:00"
revision = 1
source = "用户明确要求保存；2026-09-06；示例内容"
scope = "仅示例项目"
review_after = "2027-01-01"
+++

在示例项目的说明文档中，优先使用简短段落。
```

- `id` 是规范的小写 UUID，必须与文件名一致；脚本生成编号、时间和版本。
- `type` 仅为 `preference`、`fact`、`decision`、`lesson`、`note`；`status` 仅为 `active` 或 `archived`。
- `tags` 是可为空的字符串数组；`title`、`source`、`scope` 和正文必须非空。
- `created_at`、`updated_at` 为带时区的 ISO 8601 字符串；`revision` 为正整数。
- `review_after` 可省略，存在时是 `YYYY-MM-DD` 字符串，不是自动删除日期。
- 不接受额外字段。库格式版本和请求编号不写进条目 TOML。

一条记忆表达一个独立内容，保留限定条件与例外。统一个人库不扩大项目约定的适用范围。来源写明用户要求、真实路径、可得的原始时间与上下文，不补造会话编号、日期或链接。

## 稳定分页

- 按五种类型和有效／归档状态形成 10 个分区。内容页最多 50 条，只存标题、短摘录、日期和原文链接。
- 新条目进入分区内页号最小的未满页面；标题或正文更新不移页。归档、恢复及类型变化最多影响两个内容页。
- 不通过搬动后续条目填补空位。空页保留；显式重建也保留健康的页面归属。
- 页内按创建时间、UUID 排序，跨页不承诺全局时间顺序。全局排序通过查询接口获取。
- 导航页最多 49 个子链接及 1 个返回链接，必要时增加层级。四个入口各不超过 200 行、32 KiB；内容页不超过 64 KiB。截短仅影响展示，不改正式原文。
- 总览是维护时的快照。手工修改原文不会主动刷新总览；普通单条写入只增量维护相关页面。

## 手工修改与历史

可以直接修改 `entries` 的正文，保留合法文件头。普通编辑器造成的文件大小或修改时间变化，会在下一次明确检索时被检测，最新内容在内存中参与完整过滤、排名及分页；读取不把变化写回数据库。

若同时保持文件大小和修改时间不变，轻量检查可能发现不了该变化。明确执行 `check` 可完整读取、计算 SHA-256 并报告差异；明确执行 `rebuild` 才持久刷新索引与总览。不要为提高速度跳过这种限制说明，也不要暗中开启监控或写缓存。

修改标题、范围、标签或状态优先通过 Skill，以保留版本；不要手工改编号、版本、创建时间或内部数据库。坏格式文件保持原样并报告路径，不使用缓存旧版本伪装为最新内容。

脚本修改前保存已观察到的原文版本；无法恢复从未被观察或备份过的手工修改过程。已管理总览被手改时，覆盖前备份到 `history/views/`；未登记的同名文件不能覆盖。

归档和历史不自动清理。归档本库记忆不影响导入来源、原生记忆或原始会话，也不等于从所有来源永久删除。
